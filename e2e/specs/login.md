# 登录页表单校验测试计划

## 一、测试概述

| 项目 | 内容 |
| --- | --- |
| 测试对象 | 若依管理系统 登录页 |
| 访问地址 | `http://localhost/login`（Playwright `baseURL` 为 `http://localhost`） |
| 测试类型 | 表单必填项校验（功能测试 / 负向测试） |
| 覆盖范围 | 仅 2 个场景：账号为空校验、密码为空校验 |
| 不在范围 | 正确账号登录、错误密码提示、验证码、记住密码、注册/忘记密码等其他功能 |
| 页面标题 | 「若依管理系统」 |

> 本文档中所有元素定位与提示文案均基于在真实浏览器中打开 `http://localhost/login` 后的实际观察结果，可直接交给 QA / 开发执行或转写为自动化用例。

---

## 二、环境与前置条件

- 浏览器：Chromium（桌面端，默认视口 1280×720 即可）。
- 应用已启动，`http://localhost/login` 可正常访问，页面渲染出完整登录表单。
- 每个场景执行前均重新打开（或刷新）`http://localhost/login`，确保表单处于初始状态；若浏览器因「记住密码」自动回填了账号/密码（本次实测初始值为 `admin` / `admin123`），需先手动清空对应输入框。
- 两个场景相互独立，可单独执行、任意顺序执行，互不依赖。

---

## 三、实测页面结构与元素定位

### 3.1 页面元素

| 元素 | 实际观察到的结构 | 推荐定位方式 |
| --- | --- | --- |
| 账号输入框 | `<input class="el-input__inner" type="text" placeholder="账号">`，可访问名称「账号」 | `getByPlaceholder('账号')` 或 `getByRole('textbox', { name: '账号' })` |
| 密码输入框 | `<input class="el-input__inner" type="password" placeholder="密码">`（无 label，仅 placeholder） | `getByPlaceholder('密码')` 或 `locator('input[type="password"]')` |
| 记住密码 | 复选框，「记住密码」文本为 label | `getByRole('checkbox')` / `getByText('记住密码')` |
| 登录按钮 | `<button type="button" class="el-button el-button--primary el-button--large">`，文本为 **「登 录」**（“登”与“录”之间有一个空格） | `getByRole('button', { name: '登 录' })`，或 `getByRole('button', { name: /登\s*录/ })` |
| 表单容器 | `<form class="el-form login-form">`，表单项为 `.el-form-item`（账号、密码均为 `is-required`） | `locator('form.login-form')` |

> 补充：实际 DOM 中**不存在「验证码」输入框**（表单内只有账号、密码、记住密码复选框三个 input），无需处理验证码。

### 3.2 校验提示的显示方式（实测）

- 提示为**行内错误文本**，渲染在对应输入框正下方的表单项内，选择器为 `.el-form-item__error`，位于对应的 `.el-form-item` 容器内（账号错误在第 1 个表单项，密码错误在第 2 个表单项）。
- 出现错误时，对应表单项容器会增加 `is-error` 类；校验通过的表单项带 `is-success` 类。
- **不是 toast，也不是弹窗**：页面上没有出现 `.el-message` / `.el-notification` 之类的全局消息。
- **不跳转**：点击「登 录」后页面 URL 保持 `http://localhost/login`，仍停留在登录页。
- 实测提示文案与需求预期**完全一致**，无需做差异备注：
  - 账号为空 → `请输入您的账号`
  - 密码为空 → `请输入您的密码`

## 四、测试场景

### 场景 1：账号为空校验

**场景标题**：账号输入框为空时点击登录，提示「请输入您的账号」且停留在登录页。

**前置条件**
1. 浏览器已打开并处于登录页 `/login`（`http://localhost/login`），页面标题为「若依管理系统」。
2. 账号、密码输入框均可见，表单处于初始或已清空状态。
3. 若存在自动回填（如 `admin` / `admin123`），先清空。

**操作步骤**

1. 打开/刷新 `http://localhost/login`，等待登录表单渲染完成。
2. 定位账号输入框（placeholder 为「账号」），清空其内容，确认值为空。
3. 定位密码输入框（placeholder 为「密码」），输入占位值 `test123456`。
4. 点击文本为「登 录」的按钮。

**预期结果**

1. 账号输入框下方出现行内错误提示，文案精确为：**「请输入您的账号」**（元素：第 1 个 `.el-form-item` 内的 `.el-form-item__error`）。
2. 账号所在表单项容器带有 `is-error` 类；密码表单项不显示错误文案。
3. **不出现** toast / 全局消息 / 弹窗。
4. **仍停留在登录页，URL 仍为 `/login`**（未发生路由跳转）。

**实测复现记录**

- 清空账号、密码填 `test123456` 后点击「登 录」，页面显示的唯一错误为「请输入您的账号」，位置在账号输入框下方（行内），无 toast。
- 点击后地址栏仍为 `http://localhost/login`。
- 实际文案与预期一致。

## 五、公共断言与注意事项

- **URL 断言**：每次点击「登 录」后断言 `page.url()` 以 `/login` 结尾，或等于 `http://localhost/login`，确认未跳转。
- **提示文案断言**：使用精确文本匹配（如 `getByText('请输入您的账号', { exact: true })`），避免与页面其他文本混淆；也可直接断言 `.el-form-item__error` 的文本。
- **提示不叠加**：一次点击只应产生当前失败字段的提示；填写有效值的另一字段不应出现错误文案。
- **无 toast**：断言页面上不存在 `.el-message` / `.el-notification` 等全局提示元素。
- **按钮文本含空格**：登录按钮可访问名称为「登 录」，若用精确字符串匹配需保留中间空格；建议用正则 `/登\s*录/` 更稳妥。
- **等待策略**：点击后等待错误提示元素可见（如等待 `.el-form-item__error` 出现），不要使用固定长延时。
- **数据说明**：`test123456`、`testuser` 仅为占位/无效数据，本计划不验证真实登录成功与否。

## 六、通过 / 失败判定

| 场景 | 通过标准 | 失败判定（任一即失败） |

| 场景 1 账号为空 | 显示「请输入您的账号」；URL 仍为 `/login`；无 toast | 文案不符/未显示；发生跳转；弹出 toast 或弹窗；账号项未标记错误 |
