# medkg 原始资料采集器

这里集中存放 medkg 的 Python 采集器。每个采集器负责从指定来源发现并获取原件，Java 平台统一创建采集批次、保存原件到 OSS，并在 MySQL 登记结果。后续医学实体抽取、关系构建和图谱检索使用这些资料，属于平台后续的业务环节。

## 目录导航

```text
collectors/
├── README.md                   本目录导航与新增采集器的步骤
├── CONTRACT.md                 Python 采集器和 Java 平台的交付约定
├── medkg_collectors/
│   ├── common/                 跨来源复用的 Python 代码，例如平台交付客户端
│   └── sources/                按数据来源分目录
│       ├── china_cdc/          预留给中国疾控中心，首个目标栏目为「健康科普」
│       └── wikidata/           预留给 Wikidata 中文医学相关条目
└── tests/                      放采集器测试和小型样本，按来源组织
```

当前是目录骨架。两个来源目录均为预留位置，目录中的 `.gitkeep` 用于让 Git 保留空目录。可运行的采集器、Python 依赖清单和平台接收接口将在开发接入时补充。

## 新增一个来源时怎么做

1. 先看[已整理的数据来源和格式](../docs/2026-11-23-数据获取落库步骤.md)，确认这次要采集的栏目、入口和原件格式。例如，网页正文和网页链接的 PDF 是两份可以分别保存的原件。
2. 在 `medkg_collectors/sources/` 下选择对应来源目录。新来源使用小写英文和下划线命名。同一网站下的多个栏目可以共用一个来源目录，通过任务入口区分。
3. 按[采集器契约](CONTRACT.md)接收任务、获取原件、逐件交付并报告结束。各站点的分页、详情页识别和附件发现逻辑放在各自的来源目录。多个采集器共用的交付逻辑放进 `common/`。
4. 在 `tests/` 下按来源验证正常获取、单件失败及重复交付。样本选用小型、可随仓库共享的资料。批量采集得到的正式原件交给平台保存。

采集器开发者重点阅读契约中的「任务输入」和「逐件交付」。平台开发者还需对照「确认、去重与结束」及[原始采集表建表脚本](../sql/20261125/01_create_raw_collection_tables.sql)实现接收和入库。
