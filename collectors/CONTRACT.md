# medkg 原始资料采集契约 v1

本契约供 Python 采集器开发者和 medkg Java 后端开发者共同使用。双方统一区分三件事：采集器取得原件、平台确认单件保存、平台判定整批结果。以下字段是双方交换数据时使用的名称。具体启动命令、HTTP 路径和鉴权方式留到首次联调时确定。

## 1. 任务输入：平台交给采集器什么

平台先选择来源及入口、创建批次，再将任务交给指定采集器。一个任务对应一个批次和一个入口。

| 字段 | 要求 | 含义 |
| --- | --- | --- |
| `contract_version` | 必填，当前为 `1` | 双方按此版本解释任务。遇到无法识别的版本应报告任务失败。 |
| `collector_code` | 必填 | 要运行的采集器标识，例如 `china_cdc_health`。 |
| `batch_id` | 必填 | 平台创建的批次 ID，逐件交付和结束报告均须带回。 |
| `entry_id`、`entry_url` | 必填 | 平台配置的采集入口 ID 和起始地址。批次对应的数据来源由平台根据入口确定。 |
| `options` | 可选，默认空对象 | 当前任务的业务参数，例如约定的栏目或页数上限。各采集器应说明自己支持的选项。 |

## 2. 逐件交付：一份原件对应一条结果

每条结果都包含 `batch_id` 和原始请求信息。请求信息包括原始地址 `origin_url`、请求方法 `request_method`（GET 或 POST），以及会改变结果的业务参数 `request_params`（如分页 POST 中的页码）。地址和参数应去除访问密钥、令牌等凭据；错误说明也遵循同一规则。

| 采集结果 | 采集器交付 | 平台处理 |
| --- | --- | --- |
| 取得原件 | 原始响应内容或文件的字节流、获取时间 `fetched_at`（带时区）、原件格式 `raw_format`。能取得时附上标题 `title`、原文件名 `original_name` 和来源返回的 `content_type`。 | 按实际收到的字节计算文件大小和 SHA-256，保存至 OSS，并登记该件资料。 |
| 获取失败 | 原始请求信息和可读的失败原因，例如「下载 PDF 超时」或「预期 PDF，实际返回错误页」。 | 记录失败及尝试次数，由平台统一决定重试。 |

保留来源返回的原始 HTML、JSON、XML 或文件字节。例如，接到 JSON 后应交付原始响应，避免解析再序列化改变内容。仅返回网址、本机临时路径或抽取后的正文，不能完成原件交付。采集器使用平台提供的交付通道，OSS 和 MySQL 凭据由 Java 后端持有。

**网页与附件示例。** 一篇文章带一个 PDF，如果两者都在采集范围内，就先交付文章 HTML，再交付 PDF。每件使用各自的原始请求信息。附件另带 `parent_request`，用父页面的地址、方法和业务参数标识它，平台据此关联同一批次的父记录。PDF 下载失败时，保留已保存的文章，只报告附件失败。

## 3. 确认、去重与结束

1. **单件保存由平台确认。** 原件已写入 OSS，且对象 Key、获取时间、格式、实际字节数和内容 SHA-256 等信息已成功登记至 `medkg_raw_item` 后，平台才确认 `STORED`。如果 OSS 写入成功、数据库登记失败，平台应允许重试并核对已有对象。采集器遇到确认超时，应按同一请求重交。
2. **同批次重复交付对应同一条记录。** 平台根据请求方法、规范化地址和业务参数生成 `request_hash`，以 `(batch_id, request_hash)` 去重。对已经 `STORED` 的请求再次交付，返回已保存确认。不同批次保留各自的采集记录。`content_sha256` 校验实际文件内容，与用于识别请求的 `request_hash` 用途不同。
3. **结束报告与单件结果分开。** 采集器报告 `batch_id`、入口遍历是否正常完成，以及中断或失败的原因。入口访问失败和正常遍历后找到零条资料应明确区分。进程异常退出、来不及报告时，由平台记录中断原因。
4. **批次结果由平台汇总。** 正常遍历且所有应保存的原件均已确认，可记为 `SUCCESS`；正常遍历确认零条资料时，同时记录数量为零。部分原件保存成功、其余失败或遍历中断，记为 `PARTIAL`；发生失败且没有成功保存的原件，记为 `FAILED`。平台取消任务记为 `CANCELLED`，此前已确认的原件仍归属该批次。

平台表结构见[原始采集表建表脚本](../sql/20261125/01_create_raw_collection_tables.sql)。本契约覆盖原始资料交付。医学实体、关系和图谱数据的生成属于后续处理。
